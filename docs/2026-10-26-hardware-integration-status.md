# 数牧增效硬件与模型联调状态

任务目标仍为环境、牛身、摄像头三节点接入及视觉、声音、三位置运动模型训练与实机部署。
本记录区分已验证产物与尚未完成的实机环节。
本轮扩充后的最新结果见 `docs/2026-10-26-model-expansion-results.md`；下方原始训练表保留作基线。

## 当前实机证据

- COM5 对应环境 ESP32-S3，USB 序列号 `28:84:85:9D:78:F0`；Windows 同名蓝牙 COM5 会导致普通串口程序选错设备。
- COM9 对应牛身 ESP32-S3，USB 序列号 `14:C1:9F:2D:6A:24`。
- 2026-10-25 直接读取环境 USB 路径，得到温湿度和光照；原后端地址已过期。
- 牛身串口实际显示颈部、腿部 ADXL345 正常，背部缺失；麦克风有有效窗口，B-1 有校验通过的体表温度。
- 曾临时为 COM5 写入 UART 桥，但随后已恢复原环境应用，写入哈希校验通过，`help` 命令响应已验证。备份位于 `.run/hardware-integration-20261025`，含配置，不应公开发布。
- 用户反馈 MaixCAM 系统 WiFi 和相机应用均黑屏，单独重新上电后仍复现。此前枚举到 VID359F/PID2120 的 USB 网卡，但没有网络链路或 SSH 连接。
- 2026-10-26 的设备扫描仅见蓝牙 COM 口，未枚举到 USB 摄像头、USB 转 TTL 或两块 ESP32；当前不能读取摄像头日志或进行烧录验收。

## 已完成的软件修复

- 后端区分 COM5 环境、COM9 牛身；启动脚本可按 USB 设备实例路径连接，规避同名蓝牙串口。7 项遥测单元测试通过，实际双节点重连尚待验证。
- 摄像头串口工具只自动选择独立 USB 转 TTL，默认拒绝将 ESP32 节点当摄像头。4 项串口选择及日志凭证过滤检查通过。
- 摄像头程序响应系统退出并在异常后释放资源，部署脚本只管理自己的进程和配置，不再修改系统启动脚本或批量结束 Python/MaixVision。4 项生命周期、进程归属和凭证保留检查通过。
- 牛身固件把 SPI 恢复与 I2C/MAX30102 恢复分开，使用 500kHz SPI，增加各 CS 的 DEVID 与配置回读。断流会清空连续运动窗口。7 个基于真实固件函数的宿主测试场景通过，PlatformIO 编译通过；尚未烧录到断开的 COM9。

## 本轮扩充与接入

- 声音新增下载725段WAV，去除未知标签、短片段和重复PCM后为原40+新增512=552段；378段开发、174段保留。保留集Accuracy87.93%、Macro-F1 0.8611，咳嗽召回率83.72%。真实牛只/会话分组仍未知。
- 加速度新增6牛1391224点公开颈部记录，按整牛划分；887测试窗上时序模型85.79%，同条件旧点分类55.47%。它是四类颈部研究模型，不是三位置临床跛行模型。
- 另对站卧原分区重训并核验，候选86.06%低于原86.91%；保留原版，较弱候选仅存档，不按测试结果继续调参。
- 视觉新增7433张原图；跨库去重后274个新图像组进入训练。621张新来源留出集由86.80%提高到90.02%，旧413张固定测试由92.01%降到91.28%。保留两版与对照，不按测试结果反复调参。
- 新视觉转换产物位于 `vision-training-data/maixcam-expanded-yolo-20261026`，`.mud/.cvimodel` 哈希和参考输入对照通过；不代表已安装到设备。
- 声音研究推理已接入后台归档录音与网站，后台先复核音频哈希，再异步分析。独立H2库的历史实录回放已验证完整链路，不能算作实时牛只验证。
- 加速度时序候选已接入 `behavior.temporalResearch`，单次间隔与累计时间漂移均检查。断流清空窗口，保留原有行为/站卧和临床门禁。固件编译通过，尚未烧录。
- 后台61项测试、相关模型与摄像头检查、7个真实固件函数宿主场景及网页构建/浏览器状态验证通过。详见最新结果文档与各模态报告。

## 继续验收所需条件

1. 接回摄像头与独立 USB 转 TTL，确认新增的 USB 串口；串口 RXD 接 MaixCAM A16(TX)，TXD 接 A17(RX)，GND 共地，3.3V 电平。
2. 抓取系统控制台及应用日志，确认存储、电源、系统应用环境或后台占用的实际错误后修复。
3. 接回 COM5/COM9，恢复正确后端地址，验证双节点数据时间和命令回执。
4. 使用新固件的 `motionSpiDiagnostics` 检查背部 CS39 的 DEVID；修正实物连接后验证连续 20Hz 三位置窗口。
5. 在已通过 NPU 工具转换数值对照的基础上，完成设备模型加载和实际画面推理，验收研究外观结果展示。
6. 获取与现有三位置硬件兼容的真实临床标签和独立验证数据，才能完成疾病级模型及其生产发布。

上述未完成项仍属于原任务范围，不能以研究模型成绩或编译成功代替实机和疾病验证。
