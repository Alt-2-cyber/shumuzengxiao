# 数牧增效硬件重做版：接线、烧录与验收

## 本次实测状态（2026-09-15）

两块 ESP32-S3 已使用带 USB CDC 的固件重新烧录并运行：

| 节点 | 端口 | 固件状态 | 当前实测 |
|---|---|---|---|
| 牛身节点 | COM5 | 已烧录并运行 | 三块 ADXL345 SPI 均为 `ok`；MAX30102 `0x57` 在线；B-1 UART 帧持续收到 |
| 环境节点 | COM9 | 已烧录并运行 | SHT31 `0x44`、GY-302 `0x23`、OLED `0x3C` 均在线；MQ 暂未接入 |
| MaixCam | USB | 未枚举为 COM/磁盘/网络设备 | 当前不能确认 USB 数据链路，不能把 MaixCam 固件误烧到 COM5/COM9 |

COM5 的三块 ADXL345 已切换为 SPI 总线，COM9 的 MQ 仍未接入。大功率负载仍应按“接一个、上电、验证、再接下一个”的顺序进行，不能一次把所有模块和负载同时接上。

## 设备角色

| 设备 | 端口 | 固件目录 | 负责内容 |
|---|---|---|---|
| ESP32-S3 牛身节点 | COM5 | `硬件代码\牛身节点` | 颈部/背部/腿部运动、声音、MAX30102、B-1 |
| ESP32-S3 环境节点 | COM9 | `硬件代码` | 温湿度、光照、MQ、火焰、风扇、雾化器、报警、MaixCam UART |
| MaixCam | 当前未枚举为 Windows COM/磁盘 | `硬件代码\MaixCam节点` | 摄像头和 YOLO 边缘推理 |

两块 ESP32-S3 实测 Flash 都是 16MB。烧录和改线前先断开负载电源，所有模块
必须共地；不能把两个不确定的 3.3V 输出直接并联。

## COM5 牛身节点

### I2C 总线

COM5 的 MAX30102 使用 `D8/SDA` 和 `D9/SCL`；三块 ADXL345 不在 I2C 总线上，使用
独立 CS 的 SPI 总线：

| 位置/模块 | 地址 | 供电与地址脚 |
|---|---:|---|
| MAX30102 | `0x57` | `VCC/VIN->3V3`，`GND->GND`，`INT` 不接 |
| OLED（可选） | `0x3C` | `VCC->3V3`，`GND->GND` |

上表中的 MAX30102 和 OLED 才接 `D8/D9`。三块 ADXL345 的 SPI 接线如下：

| ADXL345 引脚 | ESP32-S3 牛身节点 |
|---|---:|
| 三块 `VCC` | `3V3` |
| 三块 `GND` | `GND` |
| 三块 `SCK` | 数字 `40` |
| 三块 `SDA/SDI/MOSI` | 数字 `41` |
| 三块 `SDO/MISO` | 数字 `42` |
| 颈部 `CS` | 数字 `38` |
| 背部 `CS` | 数字 `39` |
| 腿部 `CS` | 数字 `47` |
| 三块 `INT1/INT2` | 不接 |

SPI 模式下 ADXL345 的 `SDA` 是数据输入 `SDI/MOSI`，不能再按 I2C 的 SDA 接数字
`8`。三个模块的 X/Y/Z 方向要固定并记录。

### INMP441 六针

| INMP441 | ESP32-S3 |
|---|---:|
| `VDD` | `3V3` |
| `GND` | `GND` |
| `SCK` | `D5` |
| `WS` | `D6` |
| `SD` | `D7` |
| `L/R` | `GND` |

不要把 `SD` 当模拟量，也不要给 INMP441 接 5V。

### B-1 UART

| B-1 | ESP32-S3 |
|---|---:|
| `TX` | `D18`（ESP32 RX） |
| `RX` | `D17`（ESP32 TX） |
| `VDD` | `3V3` |
| `GND` | `GND` |

固件使用 `38400 8N1`，上电后主动发送测温请求并校验包头、长度、累加校验和、包尾。
B-1 测到的是表面温度趋势，不是核心体温。

### 牛身本地灯和蜂鸣器

外接 LED 每个串联一个限流电阻：绿灯信号 `D10`，黄灯信号 `D11`，红灯信号 `D12`，
公共阴极接 `GND`。照片所示 N16R8 开发板没有引出 GPIO13，蜂鸣器信号或驱动板输入接板上数字 `3`（GPIO3），电源按蜂鸣器模块丝印连接；
电机/大功率蜂鸣器不能直接由 GPIO 供电。默认代码按被动蜂鸣器输出 2.2kHz PWM，
若是三针有源蜂鸣器，将牛身 `include/config.h` 中的 `BUZZER_ACTIVE_MODULE` 改成
`true` 后重新编译。

## COM9 环境节点

### 传感器和执行器

| 模块 | 模块引脚 | ESP32-S3 |
|---|---|---:|
| SHT31 | `VCC/GND/SDA/SCL` | `3V3/GND/D8/D9` |
| GY-302/BH1750 | `VCC/GND/SDA/SCL` | `3V3/GND/D8/D9` |
| MQ-137 氨气模块 | `AO` | `D1`，必须先确认不超过 3.3V |
| MQ-135/烟雾模块 | `AO` | `D2`，必须先确认不超过 3.3V |
| 火焰模块 | `DO` | `D10`，5V 供电时必须做电平转换/分压 |
| 风扇驱动板 | `IN/GND/VCC` | `D14/GND/独立5V` |
| 雾化器驱动板 | `IN/GND/VCC` | `D15/GND/按驱动板要求供电` |
| 报警灯/继电器 | `IN/GND/VCC` | `D16/GND/按模块要求供电` |
| 蜂鸣器模块 | `SIG/GND/VCC` | `D21/GND/按模块要求供电` |

MQ 模块若使用 5V 供电，模拟输出不能直接进 ESP32-S3：

```text
MQ AO -- 20k -- ESP32 ADC(D1 或 D2) -- 10k -- GND
```

当前环境固件的 `ENABLE_MQ_SENSORS=false`，未接 MQ 时会输出 `nh3Raw=-1`、
`smokeRaw=-1`，不会把悬空 ADC 当成气体浓度。接线、预热和标定完成后，将该开关改为
`true` 并重新烧录 COM9。

四针模块不要把四个信号都当成数字口：

- GY-302：`VCC/GND/SDA/SCL` 四根都接，`SDA->D8`、`SCL->D9`。
- SHT31：`VCC/GND/SDA/SCL` 四根都接，和 GY-302 共用 D8/D9。
- MQ：当前只读 `A0`，所以接 `A0->D1`（氨气）或 `A0->D2`（第二路），`VCC/GND` 必接，`D0` 留空。MQ 加热丝通常需要 5V，使用 5V 时必须做上面的 AO 分压。
- 火焰模块：当前只读 `D0`，所以接 `D0->D10`、`VCC->3V3`、`GND->GND`，`A0` 留空。若模块只能 5V 供电，D0 必须先经过电平转换或分压后再接 D10。

COM9 目前只扫到 `0x3C`，说明 OLED 所在的 I2C 总线和主控基本正常；接好 SHT31、GY-302 后，重启时必须分别看到 `0x44`、`0x23`。看不到地址时先检查 VCC/GND，再检查 SDA/SCL 是否接反，最后确认模块上的地址焊盘没有改成其他地址。

风扇、雾化器、继电器必须使用驱动板或 MOSFET/继电器模块，不能直接挂在 GPIO。
大电流设备使用独立电源，并与 ESP32 共地。环境固件默认继电器低电平有效、火焰
低电平表示检测到；实物逻辑相反时修改 `include/config.h`。

### MaixCam UART

USB 线只用于 MaixCam 供电/文件传输/调试，不会自动替代 TTL 串口线。还需要：

| MaixCam | COM9 环境 ESP32-S3 |
|---|---|
| MaixCam `TX` | ESP32 `D18/RX` |
| MaixCam `RX` | ESP32 `D17/TX` |
| `GND` | `GND` |

MaixCam 和 ESP32 建议独立供电，MaixCam 使用稳定 5V、至少 2A；信号必须是 3.3V
TTL。MaixCam 的 `TX/RX` 实际引脚名称以板上丝印为准，不要仅凭线色接电源。

## 烧录顺序

关闭任何串口监视器和后端串口占用程序，然后执行：

```powershell
cd D:\table\shumuzengxiao\硬件代码
py -m platformio run -e esp32s3
py -m platformio run -e esp32s3 -t upload --upload-port COM9

cd D:\table\shumuzengxiao\硬件代码\牛身节点
py -m platformio run -e esp32s3_collar
py -m platformio run -e esp32s3_collar -t upload --upload-port COM5
```

分别查看启动日志，不要同时打开两个占用端口的程序：

```powershell
py -m platformio device monitor -p COM9 -b 115200
py -m platformio device monitor -p COM5 -b 115200
```

## 上电验收

COM5 牛身节点应看到：

```text
I2C scan:
  found 0x57
ADXL345_SPI neck/body/leg=ok/ok/ok
INMP441=...
B-1 ...
```

实际没有接 OLED 时不应把 `0x3C` 当故障。INMP441 初始会显示 `calibrating`，接线
和 `L/R` 正确后应变为 `status=ok`；`signal_invalid` 表示需要检查 VDD、GND、SCK、
WS、SD 和 L/R。MAX30102 必须稳定贴合少毛位置才会从 `no_finger` 进入测量状态。

COM9 环境节点应看到 `I2C scan` 中的 `0x23`、`0x3C`、`0x44`，并报告 `SHT31`、
`BH1750`、`OLED` 均在线；当前 MQ 未接入，遥测中的 MQ 数值应为 `null`，待接线、预热
和标定后再启用。

## MaixCam 当前状态

MaixCam 已通过 USB 网卡被 Windows 正常识别，不会作为 `COM` 串口出现。当前识别到
的设备是 `VID_359F&PID_2120`（Sipeed），Windows 端为 `UsbNcm Host Device`，主机地址
为 `10.139.183.100`，MaixCam 地址为 `10.139.183.1`，SSH `22` 端口可访问。红、蓝
指示灯亮起与此状态一致；实测 MaixPy 可以导入，摄像头可以读到 `640x480 RGB888`
图像。无需安装 CH340、CP210x 或随机 USB 驱动。

目前 MaixCam 上还没有本项目目录和牛只模型。连接后，将 `硬件代码\MaixCam节点`
复制到设备并运行：

```sh
cd /root/MaixCam节点
python main.py
```

没有模型时程序仍可启动和响应抓拍请求，但不会产生有效 YOLO 检测事件。

## 现场逐步验收

### 1. 先验 COM9 I2C

只保留 ESP32、已经在线的 OLED、SHT31、GY-302，断开风扇、雾化器、继电器和 MQ 5V 电源。接线后执行：

```powershell
cd D:\table\shumuzengxiao\硬件代码
py -m platformio device monitor -p COM9 -b 115200
```

预期地址：`0x23`、`0x3C`、`0x44`。若只有 `0x3C`，不要继续接执行器，先修复 SHT31/GY-302 的供电和 SDA/SCL。

### 2. 再验 COM5 运动传感器

COM5 的 I2C 扫描只用于确认 MAX30102；三块 ADXL345 通过 SPI 检测，不会出现在 I2C
地址列表中。预期是：

```text
MAX30102      0x57（I2C）
ADXL345       neck/body/leg=ok/ok/ok（SPI）
```

三个 ADXL345 共用 `SCK/MOSI/MISO=40/41/42`，CS 分别接 `38/39/47`。如果日志中
某一个位置是 `missing`，先断电检查该位置的 CS、VCC、GND 和三根 SPI 公共信号线。

### 3. 验 INMP441

`VDD->3V3`、`GND->GND`、`SCK->D5`、`WS->D6`、`SD->D7`、`L/R->GND`。串口中的 `INMP441=ok` 只代表 I2S 外设已创建，不代表麦克风有声音；正常接线并敲击/说话后，JSON 中 `rawMax` 应大于 0，`status` 应从 `signal_invalid` 变为 `ok` 或活动状态。

### 4. 验 B-1

B-1 官方资料要求 `3.3V`、`38400 8N1`，且必须交叉连接：B-1 `TX->COM5 D18/RX`，B-1 `RX->COM5 D17/TX`，GND 共地。固件上电后会在 5 秒协议窗口内发送命令并切换体温模式；正确时应看到 `validFrames` 增长和 `temperatureValid=true`。不要把 B-1 的 TX 接到 ESP32 TX，也不要给 VDD 接 5V。

### 5. 最后接执行器

先用万用表确认驱动板输入逻辑，再接风扇/雾化器/报警灯。GPIO 只能接驱动板 `IN`，不能直接带电机、雾化片或大功率蜂鸣器；执行器独立供电，驱动地与 ESP32 共地。主板上的红/蓝指示灯是板载状态灯，不等同于外接三色告警灯；外接 LED 需要限流电阻，代码默认按“独立绿/黄/红 LED、公共阴极”编写。

## MaixCam USB 未识别或无网络时

若以后 Windows 没有出现 `UsbNcm Host Device` 或 `Remote NDIS based Internet Sharing Device`，请按下面顺序排查：

1. 更换明确支持数据传输的 USB-C 线，并直接连接电脑主机 USB 口，不要经过无源集线器。
2. MaixCam 先用稳定的 5V 独立供电，再用另一根数据线接电脑；不要从 ESP32 的 3V3 给 MaixCam 供电。
3. 检查 MaixCam 的 USB 模式/系统是否已经启动。仅亮电源灯不能证明 USB 数据枚举成功。
4. Windows 设备管理器中出现 USB 网卡后，用 MaixVision 手动连接 `10.139.183.1`；也可以使用 MaixCAM 默认终端账号 `root`/`root` 登录后复制 `硬件代码\\MaixCam节点`。部署前还要把真实的牛只模型放到 `config.json` 的 `model_path`，当前默认的 `/root/models/cattle_yolov5.mud` 尚不存在。

MaixCam 的 USB 线和 UART TTL 线是两条不同链路：USB 用于供电、文件和调试；MaixCam `TX/RX/GND` 仍要按上表接到 COM9 的 `D18/D17/GND` 才能和环境节点交换 JSON。
