# 疾病筛查生产部署与审计清单

版本：`disease-screening-v1`。本清单面向部署人员、场长和兽医负责人。

## 上线前

1. 将 `CATTLE_ID` 改为真实耳标或管理编号；MaixCam 的 `cattle_id` 也必须是同一身份，不得使用视觉追踪编号。
2. 保存 ESP32 固件、MaixCam 程序、模型头文件和模型卡的 SHA-256；保存 MySQL 完整备份并完成一次恢复演练。
3. 执行 `D:\table\shumuzengxiao\database\migrate_existing_mysql.sql`。以 `mysql,production` profiles 启动，生产 MySQL profile 使用 `ddl-auto: validate`，迁移失败时不得启动新 JAR。
4. 将音频与 IMU 归档目录放到持久化磁盘，并限制操作系统账户的写入权限：`audio-clips/`、`motion-captures/`。
   原始音频和 IMU 下载响应必须为 `Cache-Control: no-store`，反向代理不得将其放入共享缓存。
5. 设置 `API_KEY_ENABLED=true`、精确的 `CORS_ALLOWED_ORIGINS`，以及按职责分开的 `API_KEY_VIEWER`、`API_KEY_INGEST`、`API_KEY_OPERATOR`、`API_KEY_CLINICAL`、`API_KEY_ADMIN`。密钥不得重复；`API_KEY` 仅为旧部署的管理员兼容变量。部署在 TLS 反向代理/身份系统后，不把浏览器共享密钥当作长期认证方案。
6. MaixCam 仅配置 `API_KEY_INGEST`；网页在临时局域网模式可配置只读或对应岗位密钥，但互联网部署必须改由 TLS 身份代理提供用户身份。前端 WebSocket 使用同一受限凭据，仅允许 viewer 及以上角色订阅。

## 模型批准

1. `AUDIO_APPROVED_MODEL_VERSIONS` 或 `LAMENESS_APPROVED_MODEL_VERSIONS` 只能在模型审批后写入。
2. 调用 `POST /api/model-releases` 保存同版本的 64 位数据清单哈希、模型卡哈希、固件哈希、外部验证摘要、审批人、证据编号和规范化源血缘指纹。
   音频模型在训练和登记前必须逐条回查受保护的 `GET /api/events/audio/{eventId}/training-lineage`：
   本地 WAV、平台归档 SHA-256、审核标签、耳标、录音会话、兽医、临床证据和签核时间必须完全一致。
   跛行模型在训练和登记前必须逐条回查受保护的 `GET /api/motion-captures/{sessionId}/training-lineage`：
   本地 NDJSON、平台归档 SHA-256、连续 20 Hz/完整度/丢样、会话耳标、同步视频、步态评分、蹄部检查和临床证据必须完全一致。
   登记接口会根据 `sourceLineage` 在服务端第三次重建上述档案快照并比对训练指纹；仅提交本地哈希或伪造发布摘要会被拒绝。
3. 后端只有在白名单和 `model_release.approval_state=approved` 同时成立时接受边缘疾病候选。
4. 数据漂移、标签污染、传感器缺失、误报飙升或临床不一致时，调用 `POST /api/model-releases/{id}/revoke`，清空对应白名单并重新烧录 `feature_only` 固件。撤回证据独立保存，不能修改原批准证据。
5. 模型版本是不可变发布单元：同版本只允许完全相同的幂等重试；版本已撤回或任一哈希/血缘/审批证据变更时必须使用新版本号。只使用 `tools/register_model_release.py --confirm-production-release` 登记新版本；不得以手工 SQL 绕过发布审计。

## 运行中

1. 跛行采集仅从 `/clinical` 创建。检查 `qualityStatus=accepted`、完整度 >= 95%、原始 SHA-256、同步视频和会话级步态/蹄部/兽医签核后才入库训练；`--release` 训练和模型登记均必须重新调用会话血缘接口，而非信任本地清单。
2. 声音疾病训练只使用带完整兽医签核且经平台归档重验的 WAV。人工复核标签没有兽医、真实耳标、会话和临床证据时，只能作为普通声学整理数据；
   `normal`、`moo`、`barn_noise` 也必须来自同一受控平台归档，不能混入公开或手工替换音频。
3. FMD 疑似只创建人工交接，不进行传感器“排除”。关闭须通过 `closed_by_authority`、主管/官方引用和显式授权。
4. 定期导出 `audit_record` 并校验相邻记录的 `previous_hash -> entry_hash` 链；审计链用于篡改发现，不替代数据库备份和最小权限控制。
5. 不通过数据库、`POST /api/events/health-risks` 或普通 REST 接口人工造出疾病风险。风险记录只能来自实时筛查，FMD 人工交接只能绑定一个已存在的开放 `fmd_suspect_triage`。

## 当前限制

当前工程尚未具备真实、多场、跨季节兽医签核数据与独立外部测试。因此声音疾病模型和三位置跛行模型必须保持 `feature_only`。平台提供的是采集、证据、筛查和人工分诊闭环，不是疾病确诊、处方或自动治疗系统。

乳房炎被保留为后续的独立 `mastitis_attention` 路径，但当前硬件没有乳汁电导率、SCC、挤奶量和乳样
输入，故不生成乳房炎风险，也不得把 B-1、声音、IMU 或普通视频用作乳房炎训练标签。
