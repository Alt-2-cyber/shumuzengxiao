# 疾病风险筛查模型发布与现场操作手册

版本：`disease-screening-v1`。更新：2026-07-19。

## 1. 可发布的疾病路径

| 路径 | 具体疾病/问题 | 端侧或平台允许输出 | 绝不输出 |
| --- | --- | --- | --- |
| 跛行/蹄病 | 跛行、蹄部疼痛或足病风险 | `lameness_suspect` | 腐蹄、蹄叶炎、趾间皮炎、病灶侧别或病因确诊 |
| 呼吸道 | 牛呼吸道疾病综合征（BRD）风险 | `cough_suspect`、`wheeze_suspect`、`brd_suspect` | 肺炎病原、抗菌药建议或 BRD 确诊 |
| 应急疫病 | 口蹄疫（FMD）应急筛查 | `fmd_suspect_triage` | FMD 阳性、阴性、解除隔离或自动报告完成 |
| 乳房炎 | 临床/隐性乳房炎风险（当前不启用） | `mastitis_attention` | 乳房炎、病原、乳区病灶或用药建议 |
| 非特异异常 | 采食、反刍、活动和表温异常 | `*_attention` | 酮病、酸中毒、发热或其他疾病确诊 |

每条输出均为“需要复核的证据”，不是诊断、处方或治疗命令。

## 2. 现场证据闭环

### 2.1 跛行/蹄病

1. 在 `http://localhost:5173/clinical` 选择牛只，填写同步侧视视频引用和采集人员。
2. 启动 60-120 秒 `motion_capture`。ESP32 以 20 Hz 输出颈部 MPU、背部 ADXL345、腿部 MPU 原始 NDJSON。
3. 页面显示每次会话的 `received/expected` 样本数和质量状态。只有 `accepted`、完整度至少 95%、无传感器故障、无串口背压、连续 20 Hz 索引且 SHA-256 未变化的会话可用于训练。节点断开后超时会话会自动标为 `rejected_timeout`。
4. 在页面的“步态与蹄部签核”中选择该会话，填写标准步态评分、蹄部检查人、兽医、检查结果和证据编号；平台将签核时间绑定到该归档。
5. 将同一签核中的耳标、会话 ID、评分、两位检查人、兽医、检查结果、证据和签核时间写入 `lameness_annotations.csv`。
6. 使用 `verify_lameness_manifest.py --api ... --api-key ...` 验证字段完整性、后端已接受会话、归档 SHA-256、会话签核和 NDJSON 的连续 `sampleIndex`。任何没有视频、蹄部检查、兽医签核、真实 `animalId` 或完整度不足的样本不得进入训练。
7. 训练按动物分组，保留独立动物的外部测试集。通过门禁前，固件保持 `cattle_lameness_model.h:kEnabled=false`。

只有“经批准三位置 IMU 候选”加“30 分钟内 MaixCam 步态/蹄部视觉证据”才会生成 `lameness_suspect`。它仍需人工步态评分和蹄部检查。

### 2.2 BRD 声音风险

1. INMP441 状态必须为 `status=ok`。`signal_invalid`、严重饱和或未校准槽位的录音一律丢弃。
2. 在“声音筛查”页面保存 2 秒 WAV，人工回放并记录 `normal`、`moo`、`barn_noise`、`cough_suspect` 或 `wheeze_suspect`。
3. 在声音筛查页面的“兽医临床签核”中填写真实 `animalId`、录音会话、兽医和临床证据编号。普通人工复核不能替代这一签核。
4. 导出时系统只把上述完整签核写为 `clinicalVerified=true` 和 `allowForDiseaseLabels=true`；无签核的音频只能用于普通声学事件，不能训练疾病标签。
5. `train_audio_model.py --release` 需同时满足：每个风险类至少 100 条临床签核文件、动物分组验证、风险类 Precision >= 0.80、Recall >= 0.70、Macro-F1 >= 0.75。

批准声音模型连续检出咳嗽/喘鸣候选，并伴随表温趋势、采食/活动下降、鼻液视觉证据或临床评分之一时，平台才生成 `brd_suspect`。动作是回放音频、临床复核和兽医检查，不是治疗。

### 2.3 视觉病灶和步态筛查

MaixCam 当前随项目提供的 COCO 模型只识别画面中的牛，不能判断站立、卧倒、跛行或病灶。
视觉训练必须从平台归档截图开始，逐条验证截图 SHA-256、相机、栏舍、真实耳标、采集时间、
兽医签核和临床证据。允许的输出是 `gait_abnormal_suspect`、`hoof_lesion_suspect`、
`oral_lesion_suspect`、`nasal_discharge_suspect` 等候选，不得标成 FMD 阳性/阴性。

训练器默认只生成 NumPy 数据管线基线。MaixCam 生产部署还需要独立转换的 `.mud`，并通过
外部牛只分组测试和发布门禁。登记时使用 `register_model_release.py --family vision`，
后端会重新检查每条视觉血缘；任何截图、标签或临床签核变化都会拒绝发布。

### 2.4 口蹄疫 FMD 应急分诊

`fmd_suspect_triage` 需要同时满足：

- `lameness_suspect`；
- 新鲜的 `oral_lesion_suspect` 或 `hoof_lesion_suspect` 视觉证据；
- 24 小时内由人员使用接触式体温计完成的核心体温异常复测。

B-1 只提供体表温度趋势，不能替代核心体温。系统不会因后续传感器恢复正常自动关闭 FMD 分诊记录。隔离、报告、采样、PCR/抗原/血清学检测和解除措施必须由兽医及主管部门依照当地法规决定。

平台的“临床复核”页为每个 `fmd_suspect_triage` 建立独立人工交接：兽医、证据编号和接手人是必填项。后续只能记录兽医接手、报告、隔离决定、送检、实验室引用等事实；只有同时填写主管/官方引用并显式确认授权时，才允许标记 `closed_by_authority`。该状态不是 FMD 阳性或阴性。

### 2.5 乳房炎：需要乳检硬件后才进入生产路线

当前设备不能检测乳汁电导率、SCC、挤奶量或乳样微生物学结果，因此不生成乳房炎风险。新增乳检
硬件并完成兽医标注前，B-1、声音、IMU 和摄像头只可作为一般健康上下文，不能作为乳房炎确诊或
治疗依据。后续路径固定为“乳检异常 + 乳房人工检查 + 兽医/实验室参考标准”，输出上限为
`mastitis_attention`。

## 3. 跛行训练命令

```powershell
cd D:\table\shumuzengxiao\硬件代码\现有硬件演示节点
$python = 'C:\Users\q4984\AppData\Local\Programs\Python\Python311\python.exe'

& $python tools\verify_lameness_manifest.py `
  --annotations D:\table\shumuzengxiao\疾病识别生产落地\数据采集\lameness_annotations.csv `
  --api http://localhost:8080 `
  --api-key $env:CLINICAL_API_KEY `
  --output D:\table\shumuzengxiao\疾病识别生产落地\数据采集\lameness_manifest.json

& $python tools\train_lameness_model.py `
  --manifest D:\table\shumuzengxiao\疾病识别生产落地\数据采集\lameness_manifest.json `
  --data-root D:\table\shumuzengxiao\motion-captures `
  --output include\cattle_lameness_model.h `
  --metadata tools\lameness_model_metadata.json `
  --model-card tools\lameness_model_card.md `
  --release `
  --clinical-api http://localhost:8080 `
  --clinical-api-key $env:CLINICAL_API_KEY
```

发布门禁：至少 9 头独立牛用于训练、验证和外部测试分区；外部测试至少 3 头牛和 3 头阳性牛；灵敏度 >= 0.70、特异度 >= 0.80、PPV >= 0.70、拒识率 <= 0.25、每头牛每天误报 <= 1。门禁失败时，生成头文件仍是禁用状态。

## 4. 文献与本地归档

`论文资料/论文索引.json` 记录 DOI、PMCID、许可证、原始公开链接和工程用途。已确认 PDF 文件头的资料保留为 PDF；其余开放全文保存为 Europe PMC XML。下载挑战页不是论文正文，不得作为训练或临床依据。

- Riaz et al., 2025, `10.1371/journal.pone.0325927`：加速度计足病/跛行模型的分组验证方法。
- Garrido et al., 2023, `10.3390/ani13071273`：精准畜牧 BRD 系统综述，支持多源和临床参考标准。
- Vandermeulen et al., 2016, `10.1016/j.compag.2016.07.014`：连续咳嗽监测作为 BRD 早期线索。
- Kate and Neethirajan, 2025, `10.3389/fdata.2025.1723155`：牛生物声学数据治理与可复现 ML。
- Gee et al., 2024, `10.3389/fvets.2024.1392885`：FMD 临床症状与血清学证据关系。
- Silva et al., 2021, `10.3390/ani11082253`：跛行、乳房炎和体况的精准养殖证据边界。
- Korelidou et al., 2024, `10.3390/ani14182691`：乳房炎热成像的诊断限制，不能替代乳检或临床参考标准。

## 5. 发布与回滚清单

每次发布至少归档：数据清单 SHA-256、动物/栏舍/日期分组、训练代码版本、模型头文件、模型卡、阈值、外部测试指标、审批人、固件二进制 SHA-256 和可回滚的上一版本。发现传感器漂移、标签污染、误报飙升或临床不一致时，立即回滚为 `feature_only`。

服务器对声音和跛行疾病模型使用双门禁：环境变量白名单中的版本与 `model_release` 批准记录必须同时存在。批准记录要求数据清单、模型卡和固件各自的 SHA-256、外部验证摘要、审批人、证据编号和源档案指纹；撤销后，服务器立即把该版本降回 `feature_only`。声音模型在训练、登记工具和服务器登记事务中都会重新核验每条训练 WAV 的平台 SHA-256、审核状态、兽医签核、耳标、录音会话和临床证据；跛行模型在同三个阶段逐条重新核验受保护 IMU 归档的 SHA-256、连续 20 Hz/完整度/丢样、会话耳标、同步视频、步态评分、蹄部检查与临床证据。任何一项变更都会拒绝发布。发布版本及原批准证据不可覆盖，撤回证据以独立字段和审计事件保存。所有临床复测、音频签核、IMU 会话、FMD 交接和模型审批/撤销写入 hash-chained `audit_record`。

管理员只可在临床负责人完成审批后执行 `tools/register_model_release.py --confirm-production-release`；该工具会拒绝本地训练门禁未通过的元数据，并把数据清单、模型卡和固件 SHA-256 写入服务器。发现误报、漂移或标签污染时使用 `tools/revoke_model_release.py` 撤销，再清空对应环境变量白名单并重烧为 `feature_only` 固件。

## 6. 生产部署边界

1. 先执行 `database/migrate_existing_mysql.sql`，确认 MySQL 备份与恢复演练通过，再替换后端 JAR。
2. 生产环境设置 `API_KEY_ENABLED=true`、五个独立角色密钥和 `CORS_ALLOWED_ORIGINS=https://your-console.example`；通过 HTTPS 反向代理或企业身份系统管理身份。浏览器 `VITE_API_KEY` 仅适合受控内网调试，不是长期身份体系。
3. MaixCam 配置 `backend_api_key` 后才可向受保护后端上报；不要把密钥放入版本库、截图或论文附件。
4. 现有模型没有真实多场临床数据、外部验证和审批记录，因此 `AUDIO_APPROVED_MODEL_VERSIONS` 与 `LAMENESS_APPROVED_MODEL_VERSIONS` 必须保持为空，两个疾病模型都应保持 `feature_only`。
