# 牛疾病风险筛查与生产发布规范

版本：`disease-screening-v1`。更新日期：2026-07-19。

## 不可突破的边界

本项目的传感器、声音模型、行为模型和视觉模型均用于**风险筛查**，不是疾病确诊。
所有模型输出均必须使用 `_suspect` 或 `_triage` 后缀。确诊只能由兽医临床检查与
相应实验室或影像学检测完成。

| 疾病路径 | 系统允许的输出 | 系统禁止的输出 | 最终确认方式 |
| --- | --- | --- | --- |
| 跛行/蹄病 | `lameness_suspect` | 病灶、跛行侧别、蹄叶炎或腐蹄确诊 | 标准步态评分、蹄部检查、必要时兽医诊断 |
| 牛呼吸道疾病（BRD） | `brd_suspect`、`cough_suspect`、`wheeze_suspect` | 肺炎病原、抗生素建议或疾病确诊 | 临床呼吸评分、肺部超声/听诊、兽医判断和必要检测 |
| 口蹄疫（FMD） | `fmd_suspect_triage` | FMD 阳性/阴性、自动解除隔离 | 法定报告、兽医检查、官方实验室 PCR/抗原或血清学检测 |
| 乳房炎 | `mastitis_attention`（当前不启用） | 临床/隐性乳房炎、病原或抗菌药建议 | 乳房检查、乳汁体细胞数/电导率、乳汁微生物学与兽医判断 |
| 采食/代谢异常 | `feeding_rumination_attention` | 酮病、瘤胃酸中毒等确诊 | 饲喂/反刍记录、临床检查和实验室检测 |

## 1. 跛行与蹄病风险路径

### 可用硬件证据

- 腿部 MPU：步态周期、活动强度、冲击和左右/前后不对称趋势的主要来源。
- 背部 ADXL345：躺卧、起立和姿态变化。
- 颈部 MPU：采食、反刍、静止和总活动趋势。
- MaixCam：必须补充侧视/后视步态视频，采集步长、背线拱起、头部摆动和站立时间证据。
- B-1：仅作为非接触体表温度趋势，不能用于蹄温或核心体温诊断。

### 生产门禁

1. 同一头牛不可同时出现在训练、验证和测试分区。
2. 每个跛行严重度等级必须有兽医或受训评分员的标准步态评分与检查日期。
3. 至少保留独立栏舍/日期的外部测试集；不能只报告随机切片准确率。
4. 输出至少包括灵敏度、特异度、PPV、NPV、每头牛每天误报量和拒识率。
5. 在没有经批准的三位置 IMU 模型、同步视频和临床标签之前，端侧只输出 `mobility_activity_attention`，不得把它升级为 `lameness_suspect`。
6. 三位置 IMU 会话必须达到 `qualityStatus=accepted`：20 Hz 预期样本中至少 95% 已归档、无传感器失败、原始 NDJSON 具有 SHA-256。串口背压造成的漏样一律拒绝进入训练集。

### 推荐标签

`normal_gait`、`lameness_score_1`、`lameness_score_2`、`lameness_score_3_plus`、
`hoof_lesion_confirmed`、`sensor_artifact`。其中最终部署应先以二分类
`lameness_suspect` 做筛查，不建议直接部署多个病因类别。

## 2. 牛呼吸道疾病风险路径

### 端侧声音模型

INMP441 + ESP32 必须先通过质量状态：`status=ok`、无严重饱和、I2S 槽位已校准。
模型按 2 秒窗口运行，输出 `normal`、`moo`、`barn_noise`、`cough_suspect`、
`wheeze_suspect` 或 `unknown`。`unknown` 是安全拒识，不能强制归类。

### 生产门禁

1. 风险类别必须全部由兽医签核；每条记录需含 `animalId`、`recordingSessionId`、
   `veterinarian`、`evidenceReference` 和签核时间。
2. 训练与验证按动物分组，外部测试按新的动物/栏舍/日期分组。
3. 每类不少于 100 条临床签核录音只是最低起点；生产建议达到多场、跨季节数据。
4. 发布前风险类 precision >= 0.80、recall >= 0.70、macro-F1 >= 0.75，并由临床负责人签字。
5. 连续候选必须伴随 WAV 回放、红外体温趋势、行为趋势和人工检查工单；声音事件不得自动触发治疗。
6. 网页的普通复核与兽医临床签核严格分离。疾病标签只能来自包含真实 `animalId`、`recordingSessionId`、兽医、临床证据编号和签核时间的音频记录。

### BRD 升级规则

只有当 `cough_suspect` 或 `wheeze_suspect` 已由批准模型输出，且同一时间窗内存在
至少一个独立证据（表温上升趋势、活动/采食下降、鼻液/呼吸视觉证据或人工临床评分）时，
平台才输出 `brd_suspect`。它的动作是回放音频、检查症状、联系兽医，不是确诊。

## 3. 口蹄疫应急分诊路径

FMD 是应急动物疫病。声音和 IMU 不能可靠识别或排除 FMD。项目只能识别可能需要
紧急检查的组合：持续运动/跛行异常 + 发热趋势 + 视觉发现的口鼻/蹄部病灶疑似，
并生成 `fmd_suspect_triage`。

### `fmd_suspect_triage` 最低证据

- `lameness_suspect` 或明显持续行动异常；
- 由 MaixCam 或人工现场检查上传的 `oral_lesion_suspect` 或 `hoof_lesion_suspect`；
- 体温趋势异常必须由接触式体温计复测，不得仅凭 B-1；
- 事件发生时必须锁定 cattleId、时间、栏位、视频/图片和人工检查人。

### 必做动作

1. 立即在平台创建紧急工单，停止把该结果宣传为模型诊断。
2. 隔离和报告流程必须遵守当地动物防疫法规，并由兽医/主管部门决定。
3. 采样、PCR/抗原/血清学检测和解除措施只由有资质人员执行。
4. 系统保留证据和审计日志，但不把 `fmd_suspect_triage` 自动改写为阳性或阴性。
5. 系统也不因后续遥测正常而关闭该风险。只有人工交接中的 `closed_by_authority` 动作、主管/官方引用和显式授权确认可关闭风险记录；它仍不表示检验结果。

## 4. 乳房炎路径：当前不启用，不能由现有硬件替代乳检

乳房炎是可细化的目标疾病，但当前 ESP32、INMP441、三位置 IMU、B-1 和 MaixCam 没有乳汁
电导率、体细胞数（SCC）、挤奶量或乳汁采样输入。B-1 是非接触体表温度，不能用于乳房炎确诊，
也不能把全身体表温度变化解释为乳房病灶。

### 未来可启用的最小数据闭环

1. 每头泌乳牛、每个乳区同步记录挤奶量、乳汁电导率、SCC、乳房人工检查、乳样培养/PCR（如有）和治疗/淘汰结局。
2. 平台只能先输出 `mastitis_attention`，并要求至少两个独立乳检异常来源；不得输出病原、乳区病灶、临床/隐性乳房炎确诊或用药建议。
3. 训练、验证与外部测试须按牛只、牧场和时间段隔离；治疗后的记录不得泄漏进症状发生前的训练特征。
4. 部署前必须经兽医签核，并报告敏感度、特异度、PPV、NPV、校准曲线和每头牛每天误报量。未接入乳检数据前，代码和界面不生成 `mastitis_attention`。

### 文献边界

乳房炎研究支持乳汁电导率、SCC 和热成像作为候选信息，但它们不能替代乳样、临床检查和现场验证。
现有热成像文献仅用于制定后续采集与验证方案，不授权将本项目的 B-1 表温模块直接部署成乳房炎模型。

## 5. 版本、回滚和审计

每次模型发布必须保存：训练清单哈希、模型版本、代码版本、阈值、模型卡、验证集分组、
审批人、烧录固件哈希、受保护源档案的规范化血缘指纹和回滚版本。登记接口必须重新计算
该血缘指纹，而不是仅接受训练机提交的摘要；版本一经批准不可覆盖。发现数据污染、传感器
漂移或误报异常时，立即回到 `feature_only` 或上一个经批准的版本，并将撤回证据独立归档。

### 三位置跛行筛查模型训练与发布

`http://localhost:5173/clinical` 会创建限时 `motion_capture` 会话。ESP32 在会话期间以 20 Hz
输出颈部 MPU、背部 ADXL345、腿部 MPU 原始 NDJSON；后端保存会话、视频引用、操作人员和
SHA-256。将完成的归档关联到 `lameness_annotations.csv` 后执行：

```powershell
& $python tools\train_lameness_model.py `
  --manifest D:\table\shumuzengxiao\疾病识别生产落地\数据采集\lameness_manifest.json `
  --data-root D:\table\shumuzengxiao\motion-captures `
  --output include\cattle_lameness_model.h `
  --metadata tools\lameness_model_metadata.json `
  --model-card tools\lameness_model_card.md `
  --release `
  --clinical-api http://localhost:8080 `
  --clinical-api-key $env:CLINICAL_API_KEY
```

训练器按动物分组切分训练、验证和外部测试；外部测试不足 3 头独立牛、3 头阳性牛，或未达到
灵敏度 `0.70`、特异度 `0.80`、PPV `0.70`、拒识率 `<=0.25`、每头牛每天误报 `<=1` 时，输出头文件
保持 `kEnabled=false`。即便门禁通过，IMU 候选仍需新鲜的 MaixCam 步态/蹄部证据才会升为
`lameness_suspect`。

`--release` 与后续 `register_model_release.py --family lameness` 会逐条请求受保护的
`GET /api/motion-captures/{sessionId}/training-lineage`，重新核验原始 NDJSON SHA-256、连续 20 Hz
采样、完整度、丢样、会话/耳标、同步视频、步态评分员、蹄部检查、临床证据和签核时间。任一字段
变化均拒绝发布；公开行为数据或仅手工编辑的 CSV/JSON 不能绕过该门禁。
