# 采集字段说明

## `audio_clinical_annotations.csv`

`label` 仅允许使用经过项目定义的事件标签，如 `cough_suspect`、`wheeze_suspect`、
`abnormal_vocalization_suspect`、`normal`、`moo`、`barn_noise`。
`cough_suspect` 和 `wheeze_suspect` 不是 BRD 确诊；
`abnormal_vocalization_suspect` 也不能单独解释为疼痛、应激或某种疾病。
`evidenceReference` 应指向临床呼吸评分、肺部超声、听诊、疼痛/应激检查或病例记录。

## `lameness_annotations.csv`

`lamenessScore` 必须来自人工标准步态评分。`hoofFinding` 是兽医检查结论，不能只依据
IMU 或视频推断。`gaitReviewer`、`hoofExaminer`、`veterinarian`、`clinicalEvidenceReference` 和
`verifiedAt` 必须与临床页面中同一 `recordingSessionId` 的会话签核逐项一致。`videoReference` 和
`imuReference` 用于核验多模态样本是否同步。

平台新建的 `motion_capture` 会话会生成带会话 ID 的 NDJSON 和 SHA-256。`imuReference` 应指向
`GET /api/motion-captures/{sessionId}/raw` 下载后的归档文件或等价的受控存储位置；不得引用日常
聚合遥测。每条有效样本都要关联真实 `animalId`、同步侧视视频、步态评分人和蹄部检查人。

生成清单时 `verify_lameness_manifest.py --api ... --api-key ...` 会通过
`GET /api/motion-captures/{sessionId}/training-lineage` 交叉检查耳标、哈希、视频引用、20 Hz 与丢样状态。
它还返回并核对会话级步态/蹄部/兽医签核。训练、模型登记工具和服务器登记事务会执行三次在线血缘复核，
不接受仅靠手工编辑 CSV 或 JSON 通过门禁的记录。

## `fmd_triage_observations.csv`

该表用于应急分诊留痕。`coreTemperatureVerified` 只有在接触式体温计、兽医或受训人员
复测后才能填 `true`。它不替代实验室检测或法规规定的报告程序。
